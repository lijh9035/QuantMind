# QuantMind 模型训练与模型管理操作手册

适用范围：QuantMind 本地部署，AI-IDE 工作目录说明，以及 A 股（CN）QuantDB 直读训练。本文覆盖“理解工作目录 → 准备训练数据 → 发布训练特征目录 → 训练模型 → 模型入库并设为默认模型”。

本文根据当前仓库的前端、后端和部署文档整理。模型训练界面后续可能更新；如按钮名称有差异，以当前页面提示和当前源码为准。

## 一、AI-IDE 工作目录怎么切换

先看你打开的是哪一种页面：本手册针对浏览器里的 QuantMind 页面（例如 `http://127.0.0.1:3001/#/ai-ide`）。浏览器版 AI-IDE 的文件树由后端 AI-IDE 服务提供，不是 Windows 文件选择器，因此不能直接输入或浏览 `E:\...` 任意目录。

当前页面左侧文件树可以进入子文件夹，顶部的“返回上级”只是在当前工作区内导航；它不会选择一个新的根目录。源码中切换市场时会把工作区根目录设为 `strategies/{市场代码}`，例如 CN 对应 `strategies/cn`。当前浏览器页面没有可操作的“选择任意工作目录”按钮。

因此，若你要把 AI-IDE 指向另一份本机项目目录，当前版本没有完整的页面操作流程；不要把“返回上级”或新建文件夹当作更换工作区。需要应用提供目录选择入口，并由后端明确允许该目录后才能安全切换。Electron 文档提到的目录选择 IPC 在本次核对的页面调用链中没有形成可用的选择入口。

## 二、先分清三种“模型”

| 名称 | 作用 | 是否会出现在模型管理列表 |
| --- | --- | --- |
| 训练算法 | LightGBM、XGBoost、CatBoost、Ridge、GRU 等训练选项 | 不会；它们是训练方法，不是已训练模型 |
| QuantMind 训练模型 | 用 QuantDB 因子和训练标签拟合得到的模型资产 | 会；训练成功并完成模型注册后出现 |
| Ollama 对话模型 | 例如 Qwen，用于 AI-IDE 等对话和文本生成 | 不会；它不是 QuantMind 的选股预测模型 |

首次使用不需要先下载一个“模型包”。先完成训练目录发布，再运行一次 LightGBM；成功注册后才会出现 QuantMind 模型资产。如果模型广场展示了可导入的模型包，也可以从模型广场导入，但这不是首次训练的前置条件；当前 WSL 部署的 models/ 目录为空，不能据此认为本机已有预训练模型。

## 三、训练前检查数据

1. 登录 QuantMind 管理员账号。
2. 打开 **管理后台 → 训练服务 → 数据发布**。
3. 选择市场 **A 股（CN）**，数据源选择 **L1 因子（l1_factors）**。
4. 查看数据源卡片中的分区文件数、日期覆盖和字段数。若提示数据未同步，先到 **个人中心 → 数据平台** 或 **管理后台 → 数据管理** 完成 QuantDB 数据同步，再返回此页。
5. 有数据后点击 **字段发现**，刷新后端记录的可用字段。字段发现只扫描数据，不会训练模型，也不会发布目录。

训练页面读取的是已发布的训练特征目录。只有草稿而没有发布版本时，A 股训练页会显示“尚未发布因子目录”，特征列表可能为空，训练按钮也不会就绪。

## 四、创建并发布训练特征目录

在 **管理后台 → 训练服务 → 数据发布** 中完成：

1. 保持 **CN / L1 因子** 数据源。
2. 确认字段发现结果包含可训练字段；若数据源提示缺少必需行情字段，先补齐数据再刷新字段发现。
3. 在“分类映射草稿”输入版本名称，例如 `CN-L1-首次训练`，点击 **新建草稿**。当前界面会为发现的字段建立映射并套用默认配置。
4. 浏览字段目录，确认要使用的字段已启用，并检查默认勾选字段。首轮可以保留默认映射。
5. 点击 **发布此草稿**。
6. 回到 **模型训练中心**，刷新页面；确认数据源旁出现目录版本号、特征数大于零，训练数据状态就绪。

已发布版本用于后续新训练任务。需要调整映射时，创建新的草稿并发布新版本；训练任务会记录其使用的目录版本。

## 五、运行第一次训练

进入 **模型训练中心**。页面从左侧步骤导航依次完成配置；可随时点步骤名称返回修改。

### 第一步：特征选择

- 市场选择 **CN / A 股**，数据源选择已发布目录对应的 **L1 因子**。
- 首次训练可先保留目录的默认勾选特征。
- 默认全市场；只有明确要限制样本时才选择训练股票池。
- 页面显示的特征数应大于零。若为零，先检查第二节的目录版本和默认勾选字段。

**因子筛选和因子挖掘是两件事。** 训练页的筛选是在已选输入字段中做 IC、相关性剪枝和滚动稳定性筛选，不会生成新的研究因子。当前默认开启，Top-N 为 80，筛选默认阈值为绝对 IC 不低于 0.01、绝对 ICIR 不低于 0.15、相关性阈值 0.9，并检查约 60 个交易日的滚动稳定性；具体入模字段数可能小于勾选数，结果页可以查看每个字段的保留或淘汰原因。第一次训练先保留默认值，之后再按结果调整。

### 第二步：训练目标

- 选择预测目标和持有期，例如收益预测、T+5 或 T+10。
- 设置训练、验证、测试时间范围，并确认落在数据覆盖区间内。
- 不确定时先使用数据目录给出的建议范围；不要让测试区间与训练区间重叠。

常见预测周期为 T+1、T+3、T+5、T+10，也可在页面允许范围内填写自定义周期。训练、验证、测试区间按时间顺序排列并保持不重叠；后台会按交易日历校正实际生效日期。数据目录覆盖某日期，不代表该日期所有标的都有有效标签。

### 第三步：参数配置

- 首次基线建议选择 **LightGBM**，使用页面默认参数。
- 页面中的模型类型是算法选项，不需要预先导入模型权重。
- 后续再分别尝试 XGBoost、Ridge、RandomForest 或深度学习模型，便于比较增量。
- 检查任务名称、市场、基准、目标周期和训练区间摘要。

当前前端算法选项包含 LightGBM、XGBoost、CatBoost、RandomForest、Ridge、MLP、GRU、LSTM、ALSTM、Transformer、TabNet、TCN 和 NativeTFT；实际可用算法还受训练节点和依赖影响。一次图形界面训练只选择一个模型类型。LightGBM 默认参数包括学习率 0.02、叶子数 31、每叶最小样本 300、特征采样 0.7、行采样 0.8、最多 2000 轮和 early stopping 50 轮；这些是首轮基线起点，不是跨数据集的最佳配置。

训练上下文里的基准、初始资金、手续费、滑点和开盘/收盘价格选项也会影响收益口径；比较模型时尽量保持不变。Walk-forward 稳定性诊断会追加多个训练窗口，只在普通基线完成后再启用；它只对页面注明支持的树模型和线性模型开放。

### 第四步：执行训练

1. 在左侧 **训练执行配置** 选择状态为就绪的训练节点。首次使用先选本地节点；只有已配置并就绪的 AutoDL 节点才选远程节点。
2. 若节点显示 `offline` 或 `warning`，先点 **刷新** 查看提示并解决节点问题；不要通过切换算法来绕过节点未就绪状态。
3. 检查右侧请求预览、特征数、日期范围和股票池。
4. 点击页面右上角 **开始训练**。
5. 在执行训练页查看状态和日志。`waiting_callback` 表示训练进程结束后仍在等待后端完成回调；先查看状态变化和日志，不要据此认定模型已入库。

远程节点按节点自身的数据窗口检查训练日期；本地节点由容器执行训练。页面的训练时长上限是系统配置，不能因页面一直显示运行中就反复提交重复任务。**训练后释放容器**开关可能停止其他 Docker 容器；共享 Docker 主机上先确认影响再开启。

### 第五步：查看结果入库

训练结束后查看 **模型注册与同步状态**：

- **ready**：模型文件和注册记录已就绪，可以设为默认模型。
- **syncing**：训练结果正在同步，等待状态更新后再使用。
- **failed**：注册或同步失败；查看训练结果和后端错误信息，再处理失败原因。
- **candidate**：模型已登记但处于候选状态；先检查测试集指标和模型管理页给出的状态说明。

状态为 **ready** 时，可点击 **设为默认模型**，再点击 **前往模型管理中心**。模型管理中心会列出已登记的模型；模型管理列表为空时，也可以从该页点击 **去训练模型**。

## 六、如何判断空列表属于哪种情况

| 页面现象 | 含义 | 处理方式 |
| --- | --- | --- |
| 参数配置里的算法选择为空 | 与数据库里有没有已训练模型无关；当前仓库把算法选项定义在前端 | 刷新前端并检查浏览器 Console/Network；确认当前客户端加载了匹配版本的前端资源 |
| 特征选择列表为空，或数据源标为“尚未发布因子目录” | 没有可用的已发布训练特征目录，或数据源本身未就绪 | 回到“训练服务 → 数据发布”，检查同步状态、字段发现和发布版本 |
| 模型管理中心显示“暂无模型” | 当前用户尚无已注册模型；新部署或未完成训练时是正常状态 | 完成一次训练，并在第五步确认注册状态为 `ready` |
| 训练节点未就绪 | 训练执行环境不可用 | 刷新节点状态，按页面提示修复本地训练镜像，或选择已就绪的远程训练节点 |
| 训练完成但列表仍为空 | 训练计算结果和模型登记是两个环节，可能卡在回调或产物同步 | 回到第五步查看注册状态和错误信息；确认 `model_id` 和模型产物已生成 |

- 数据库已发现 120 个 L1 字段。
- `qm_training_factor_catalog_version` 没有目录版本，`qm_training_factor_mapping` 没有映射记录。
- `qm_user_models` 没有模型记录；部署目录的 `models/` 为空。
- 因此这套实例不需要为了出现第一条模型记录去找预训练模型包；应先在管理后台发布 CN/L1 训练特征目录，再完成一次训练。
