# QuantMind 策略回测与组合操作手册

适用范围：QuantMind 回测中心中的模型信号组合回测、历史策略比较，以及 AI-IDE 中的 Python Strategy Lab 回测。本文以当前仓库中的页面和请求流程为准。

## 1. 先分清“组合”指什么

QuantMind 中有几种容易混淆的功能：

| 功能 | 实际用途 |
|---|---|
| 模型驱动快速回测 | 一个训练模型的分数 + 一个 Qlib 策略模板 + 股票池和回测区间，生成一条组合回测 |
| 策略对比 | 选取多条已完成回测并排比较，不合成新策略 |
| 推理中心多模型 | 同一轮个股推理最多选择 6 个模型并行推理，首个是主模型；不等同于策略权重组合 |
| Strategy Lab | 在 Python 沙盒中研究和回测一段自编策略代码 |
| 我的投资组合 | 旧页面展示账户资产、现金和持仓；当前个人中心没有挂载可操作入口，也不能配置策略权重 |

如果你想把策略 A、B 按固定资金比例合成为一个账户组合，当前代码中没有找到可操作的策略权重组合入口。当前可用的主流程是单模型信号加单策略模板做回测，再比较多个回测结果。

## 2. 回测前准备

开始回测前确认：

1. 至少有一个与目标市场匹配的已登记模型，模型注册状态为可用。
2. 模型需要产生可供策略读取的分数；模型训练完成但尚未注册/同步就绪时，回测模型列表可能为空。
3. 准备股票池、开始与结束日期、基准和初始资金。
4. 选定成交价格口径、手续费、滑点和调仓频率。首次做对照时把这些口径固定下来。
5. 记录实验条件，至少包括模型 ID、策略模板、股票池、日期、资金、费用和调仓参数。

一次训练任务对应一个模型。若要比较多个模型，应分别训练、登记并在相同回测条件下运行。

## 3. 快速回测：模型信号 + 策略模板

### 第一步：选模型和股票池

1. 打开主导航 **回测中心**。
2. 左侧选择 **快速回测**。
3. 从模型选择器中选一个已就绪模型。模型分数作为选股信号。
4. 选择市场和股票池，或按页面提示使用系统指数范围。
5. 若模型列表显示为空，先检查模型管理中的模型状态、当前市场筛选和当前登录用户。

### 第二步：设置回测窗口与资金

1. 设置回测起止日期。建议保留一段未参与模型训练或因子挖掘的测试期。
2. 设置初始资金。
3. 选择基准指数。
4. 选择调仓周期。日调仓、周调仓和月调仓的换手与成本不同；第一次使用模板默认值。
5. 检查成交价格类型及费用、滑点。若用开盘成交或收盘成交，所有比较都沿用同一规则。

### 第三步：配置策略模板

选择模板后检查参数，不要只看模板名称：

- **Top-K**：按模型分数排序后保留分数靠前的 K 个标的。
- **n_drop**：每次换仓时从已有持仓中剔除的标的数；不能大于 Top-K。
- **得分加权**：仓位权重随模型分数变化，不是简单等权。
- **多空 / 轮动模板**：按页面提供的参数配置，并检查系统是否支持目标市场和交易方向。
- **自定义策略**：若页面提供自定义代码入口，先确认请求预览和参数，不要假设与 AI-IDE 的 Python SDK 相同。

首轮建议用默认模板参数跑通基线。之后一次只调整 Top-K、n_drop、调仓周期或模型中的一个因素，便于判断结果变化来源。

### 第四步：提交并等结果

提交前再次确认请求预览中的：

- 模型 ID 和市场；
- 股票池和日期范围；
- 策略类型和参数；
- 初始资金、基准、成交价格和费用设置。

等待回测完成后查看结果页面。HTTP 请求成功或任务进入队列都不等于回测结果有效；应检查实际持仓、成交和净值序列是否生成。

## 4. 如何读回测结果

至少一起检查：

| 指标 / 结果 | 关注点 |
|---|---|
| 总收益、年化收益 | 区间长度、收益是否集中在少数交易日 |
| 基准收益、超额收益 | 策略是否在承担市场风险后仍有增量 |
| Sharpe | 风险调整后收益，不要脱离回撤单独看 |
| 最大回撤 | 下跌幅度和恢复时间是否可接受 |
| 权益曲线、回撤曲线 | 是否阶段性失效、是否存在长时间回撤 |
| 交易和持仓明细 | 成交是否符合规则，持仓是否过度集中 |
| 换手和费用 | 高频换仓的收益是否被成本侵蚀 |
| 成交价格类型 | 是否与研究和实际执行口径一致 |

若策略依赖模型分数，注意把模型训练测试窗口与策略回测窗口分开。回测只反映指定数据和规则下的历史模拟，不是未来收益保证，也不证明实盘成交可实现。

## 5. 策略对比：比较独立回测结果

1. 先完成两条或更多回测。
2. 在回测中心切到 **策略对比**。
3. 选择需要比较的历史回测记录。
4. 对照收益、风险、持仓、费用和参数差异。
5. 只改变一个重要变量，再跑一组结果；把回测 ID 和实验条件保存下来。

策略对比只负责并排展示已有回测，不会自动计算策略 A/B 权重，也不会创建一个新的多策略组合。

## 6. 专家模式、历史、参数优化和策略管理

回测中心左侧还提供 **专家模式、历史、参数优化、策略管理和高级分析**：

- **专家模式**：用于手动配置更多策略参数；先看请求预览，确认模板、模型、股票池和日期都符合预期。
- **历史**：检查已完成任务和结果；用回测 ID 对应实验记录。
- **参数优化**：用于探索 Top-K、n_drop 等策略参数。优化结果是候选参数，不应直接当作独立样本外验证。
- **策略管理**：搜索、编辑或维护云端策略。保存策略模板与已经运行过一次回测是不同状态。
- **高级分析**：进一步查看分层收益、归因或持仓表现；指标需结合相同的基准与时间窗口解释。

注意参数优化会在同一历史数据上试多个配置，容易发生选择偏差。优化后应留出未参与搜索的独立时间段复核。

## 7. Strategy Lab 与模型驱动 Qlib 回测的区别

Strategy Lab 适合用 Python SDK 编写单策略逻辑，并在受限沙盒中运行；它与模型驱动 Qlib 快速回测是两条不同链路。

当前独立的 **/strategy-lab** 页面会重定向到 **AI-IDE**。在 AI-IDE 中选择或编写 Python 策略，点击 **运行**，结果出现在下方运行/回测区域。Strategy Lab 的 Python 沙盒禁止任意文件、网络和子进程访问；只使用页面说明的 SDK API。旧版文档所说的独立“策略实验室”侧栏入口不一定适用于当前 UI。

如果你要把模型预测分数作为选股信号并配置 Top-K 等模板，应回到 **回测中心 → 快速回测**。不要因为两个页面都显示“回测”就假设它们共享同一参数和产物。

## 8. 从回测进入模拟调仓

通过研究回测之后，若要演练调仓：

1. 在 **推理中心**选择已就绪模型和推理日期，生成推理结果。
2. 在 **交易 → 手动任务**按向导选择模型、已完成推理批次和策略。
3. 生成调仓预案，检查买卖标的、目标权重、资金和风控提示。
4. 先在模拟交易流程中核对成交和持仓变化。

回测任务不会自动生成生产推理批次，也不会自动向交易端下单。实盘交易涉及单独的账户、权限、风控和启动操作；本手册只说明研究和模拟验证链路。

## 9. 当前策略组合能力边界

依据当前源码：

- 快速回测请求选择一个模型和一个策略模板；
- 策略对比只对比已完成回测；
- 推理中心的多模型选择是多模型推理，不是多策略资金权重；
- 旧投资组合创建表单没有策略选择和策略权重；当前个人中心也未挂载该页面。

因此，当前教程不提供“把多个策略按百分比合并”的点击步骤，因为 UI 和 API 中没有找到该操作入口。如果未来版本增加多策略组合，应重新核对前端和后端实际实现后再补充。
